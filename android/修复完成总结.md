# ✅ 安卓客户端视频播放修复完成

## 问题描述

用户反馈：**填写后台地址登录后还是无法观看视频，是不是UI和后端没有连接起来？**

## 诊断结果

✅ **UI 和后端已经连接起来**，问题不在连接本身，而在于：

ExoPlayer 播放视频时，**缺少必要的身份验证请求头**，导致后端无法识别用户身份。

### 技术分析

| 组件 | 状态 | 说明 |
|------|------|------|
| API 连接 | ✅ 正常 | `ApiClient` 已正确配置，可以获取剧集列表、详情 |
| 登录功能 | ✅ 正常 | 可以正常登录，获取 `viewerId` |
| 播放地址获取 | ✅ 正常 | 可以调用 `/api/ui/playback/plan` 获取播放URL |
| **ExoPlayer 请求** | ❌ **缺少请求头** | 播放视频时未携带 `X-Juku-Viewer` 和 `Sec-Fetch-Site` |

## 修复方案

### 修改的文件

1. **PlayerScreen.kt** - 播放器组件
   - 位置：`android/app/src/main/java/com/juku/app/ui/player/PlayerScreen.kt`
   - 修改：为 ExoPlayer 配置自定义 HTTP DataSource，自动附加必要的请求头

2. **MainScreen.kt** - 主界面
   - 位置：`android/app/src/main/java/com/juku/app/ui/MainScreen.kt`
   - 修改：传递 `viewerId` 给播放器组件

### 关键代码

```kotlin
// PlayerScreen.kt - 配置自定义 DataSource
val httpDataSourceFactory = DefaultHttpDataSource.Factory()
    .setUserAgent("JukuApp/1.0")
    .setConnectTimeoutMs(15000)
    .setReadTimeoutMs(20000)
    .setAllowCrossProtocolRedirects(true)

if (viewerId.isNotBlank()) {
    httpDataSourceFactory.setDefaultRequestProperties(
        mapOf(
            "X-Juku-Viewer" to viewerId,
            "Sec-Fetch-Site" to "same-origin"
        )
    )
}

val mediaSourceFactory = DefaultMediaSourceFactory(context)
    .setDataSourceFactory(httpDataSourceFactory)

ExoPlayer.Builder(context)
    .setMediaSourceFactory(mediaSourceFactory)
    .build()
```

```kotlin
// MainScreen.kt - 传递 viewerId
PlayerScreen(
    drama = activeDrama!!,
    chapters = activeChapters,
    currentEpisodeIndex = activeEpisodeIndex,
    videoUrl = activeVideoUrl,
    viewerId = repository.apiClient.getViewerId(), // ← 新增
    danmakuList = danmakuList,
    onBack = { activeDrama = null },
    onEpisodeChange = { newIdx -> openDrama(activeDrama!!, newIdx) },
    onProgressUpdate = { pos, dur -> ... }
)
```

如果编译或测试时遇到问题：
